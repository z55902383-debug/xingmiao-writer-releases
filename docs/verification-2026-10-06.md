## 已修复

1. 退出登录后，旧轮询仍可写入会话。增加登录代次校验、取消与加密后再次校验。
2. 更换后端后旧令牌可发往新地址。切换时清理会话和轮询，拒绝带凭据、查询或片段的服务地址。
3. 慢网络导致轮询重叠。增加串行保护、请求时限和重定向拒绝。
4. 请求仅看 JSON 的 ok，HTTP 401 被异常 body 掩盖。改为同时判断 HTTP 与业务状态。
5. 任意 xingmiao:// 链接中的未验证 token 可写入本地账号。会话统一从本次随机 state 对应的后端轮询领取。
6. 旧说明把明亮主题、安装更新写成未实现，版本号也过期。更新文档和 0.6.2 发布记录。
7. 发布辅助脚本固定读测试版产物。补充 --release-dir，完整版可生成自己的更新清单。
8. 安装包缺少集中运行时第三方许可。新增锁文件生成流程与随包分发。

## 建议增加的模块（未擅自扩展产品）

| 优先级 | 建议 | 原因 |
| --- | --- | --- |
| P1 | 定时备份、轮换与一键恢复检查 | 正常关闭保存不能覆盖断电、磁盘损坏；目前主要靠手动备份 |
| P1 | 服务健康提示、登录取消按钮及超时反馈 | 目前轮询超时后缺少清晰结果提示，需提升在线故障可感知性 |
| P1 | 真实服务验收与账号后端部署回归 | 本机模拟回归不能证明远程 OAuth、权限、封面和更新源在线可用 |
| P2 | 章序调整与全书查找替换 | 需定义变更后记忆失效和时间线重排规则再实现 |
| P2 | DOCX 导出、TXT/Markdown 整书拆章导入 | 方便投稿与迁移，需要保留章名、排序和编码 |
| P2 | AI 用量/请求历史、失败重试、封面停止与网络时限 | 提升费用透明度与网络异常体验 |
| P2 | 记忆失效批量复核/重建、人物别名管理 | 长篇维护成本较高；不宜直接让模型覆盖全部事实 |
| P3 | 跨设备同步与协作 | 需先解决版本冲突、加密和权限，不是当前本地版发布的必备项 |

## 未覆盖与已知限制

- 本次没有使用真实账号发布广场内容，没有请求付费模型或真实生图，也没有修改远程 Supabase 部署。
- 后端飞书回调、一次性 token 领取和 JWT 实现做了源码检查，但没有 Deno/真实服务器的端到端验收；建议上线前补注册 state、原子领取、限流、过期清理和 OAuth 失败反馈。
- 真实 GitHub 更新需要先上传此次安装包与 latest.yml；本次没有远程发布。
- 没有在第二台干净 Windows 电脑执行安装/卸载/升级流程；安装包本身生成完成，可运行程序另做隔离启动检查。
- 安装包未配置代码签名证书。构建日志的 signing 字样不是已经签名的证据，结果以 Authenticode 状态为准。
- Vite 提示入口包大于 500 kB，属于性能建议，不是构建失败。SQLite 实验性与模块类型提示也不是测试失败。
- 受保护构建的压缩和 ASAR 完整性检查不能保证源码无法逆向。
